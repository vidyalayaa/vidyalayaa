# Architecture decisions and acceptance ownership

Updated 20 October 2026. Requirements come from the supplied architecture specification and the role audit. A default below is an implementation choice, not an invented contractual or legal approval.

| Topic | Implemented decision | Approval / remaining evidence |
|---|---|---|
| Primary roles | Super Admin, School Admin, Principal, Parent and Student. Teacher features remain only where documented; teacher is not an extra primary role in the audit scope. | Owner's explicit scope. |
| Identity | Supabase Auth remains authoritative for password, Google PKCE, session and TOTP. Firebase is Hosting and FCM. Google does not grant a school or platform role. | Google OAuth client and staging identity acceptance remain external. |
| Billing | Manual Super Admin subscription administration, reason and optional contract/payment reference. No checkout or bank collection. Billing webhook stays disabled. | Owner selected manual billing. |
| Firmware | All embedded development and hardware acceptance deferred until the full website is complete. Existing prototype and unfinished production source are retained. | Owner's explicit scope change. No firmware release approval. |
| School MFA | Platform always requires aal2. School Admin records an approved policy reference for privileged MFA, recent step-up and student login. Enrolled factors require verification for every role. | Each school's policy and recovery process require its named approver. |
| Account recovery | Use verified Supabase recovery, or a documented identity-checked operator recovery when factors are lost. No school API resets platform privileges or removes verified factors. | Operator must record identity evidence, dual review for platform recovery, incident/ticket reference and subsequent audit; never collect passwords or OTP seeds in a ticket. |
| Family privacy | Parents see only currently authorized child links. Students see self-only records and cannot mutate school business records. PARENTS announcements exclude students. | Conservative audience resolution; confirm school notices and student age policy before launch. |
| Marks | Family results show published assessments. Percentages use recorded marks and exam maxima. The leadership dashboard ranks complete published results with shared positions for ties. | School Admin can enter the school's approved grade bands and overall pass percentage. |
| Push | Lock-screen messages omit names by default; an authorized parent may change that preference. Token ownership is rechecked when sending. | Actual FCM browser/account switching acceptance remains. |
| External delivery | At least once; stable provider idempotency where supported. Provider acceptance is not proof of receipt/read. Email/SMS fetches time out after 10 seconds; installed Firebase Admin bounds messaging requests at 15 seconds. | Live provider, sender/template, retry and on-call exercises remain. |
| Data lifetime | Subscription expiry is separate from closure/deletion. Closure requires distinct platform and school approvals, drained readers, export deadline, deletion date and legal policy reference. Legal hold defaults on. Global identities, immutable audit and required contract metadata are retained by operational purge. | Contract owner/counsel decide lawful retention, consent, hold removal, backup aging and erasure obligations. No automatic blanket legal erasure is claimed. |
| Export access | Terminal subscriptions need an explicit contractual export deadline. School Admin retains billing/support access; export rights end at the recorded deadline. Closed schools use full-school exports. | Owner must approve each contract window; no unlimited default. |
| Multi-campus | Enterprise organization association never grants membership. Campus views require current explicit membership and the same organization. | Actual organization ownership/contract approval remains external. |
| Operations | Separate non-bypass runtime database roles; forced tenant RLS plus API user/ownership checks. Sentry is optional, with an explicit privacy filter. | Configure service regions, PITR, monitoring retention, alert receivers and protected release environments for the selected accounts. |

The original audit stays unchanged as historical evidence. `AUDIT_IMPLEMENTATION.md` records changes and tests. External privacy approval, independent security review, provider delivery and cloud recovery cannot be substituted with synthetic tests.


Schema ownership exceptions are explicit: schools, users, organizations, roles, permissions, role_permissions, platform_staff, subscription_plans and firmware_releases are global reference/identity/platform data; worker_instances and provider_buckets are fleet/provider operations; billing_webhook_events is a global idempotency ledger retained while billing stays manual. audit_logs may have no school for global platform/authentication actions. All public tables force RLS. The ownership test checks every other table has non-null school_id, every tenant-to-tenant relationship includes both school keys, and neither browser role has direct application-table privileges. A new exception requires review rather than silently inheriting broad access.
